# Agent Spec: CalendarBot ADK Agent

## Overview

An ADK-based agent that integrates a Telegram bot with Google Calendar. When a user sends a natural-language message to the Telegram bot (in English or Russian), the agent extracts event information (title, date, time) using Gemini, authenticates via Google OAuth 2.0, and creates an event in the user's Google Calendar.

The agent is deployed on **Cloud Run** and uses the ADK framework with a FastAPI app layer. Telegram integration happens via webhooks. User-specific Google OAuth tokens are stored encrypted in SQLite (via SQLAlchemy + Fernet). OAuth state (CSRF tokens) is stored in Redis.

## Example Use Cases

| Input | Expected Output |
|-------|----------------|
| "Meeting with Bob tomorrow at 5pm" | Creates Google Calendar event titled "Meeting with Bob", date = tomorrow, time = 17:00 |
| "Встреча с командой в пятницу в 14:00" | Creates event "Встреча с командой" on Friday at 14:00 |
| "Doctor appointment" (no time/date given) | Prompts user for date and time via Telegram inline buttons |
| `/start` (new user) | Returns Google OAuth URL to authenticate |
| `/start` (returning user) | Shows a list of user's Google Calendars to set default |

## Tools Required

1. **`parse_event_text`** — Extract title, date, time from natural language using Gemini structured output. Supports English and Russian.
2. **`get_google_auth_url`** — Generate the Google OAuth 2.0 authorization URL for a given Telegram user ID. Stores CSRF state in Redis.
3. **`create_calendar_event`** — Create a Google Calendar event given title, date, time, calendar ID, and stored user credentials.
4. **`get_user_calendars`** — List the user's Google Calendars (for calendar selection on first use).
5. **`get_user_credentials`** — Look up stored (encrypted) Google credentials for a Telegram user from SQLite.
6. **`set_default_calendar`** — Save the user's chosen default calendar ID to SQLite.

## External Integrations

- **Telegram Bot API** — via aiogram v3, webhook mode (POST /webhook)
- **Google Calendar API** — google-api-python-client, OAuth 2.0
- **Google Gemini API** — google-genai, structured output for event parsing
- **SQLite** — SQLAlchemy ORM, Fernet-encrypted credentials column
- **Redis** — OAuth state CSRF token storage (10 min TTL), aiogram FSM state storage

## Constraints & Safety Rules

- NEVER create events without user confirmation if date/time is missing
- NEVER store or log raw OAuth tokens in plaintext — always encrypt with Fernet
- NEVER expose the webhook endpoint without validating the `X-Telegram-Bot-Api-Secret-Token` header
- NEVER call Google Calendar API for a user without first checking their credentials are present
- Do NOT allow the agent to modify or delete existing calendar events

## Architecture

```
Telegram → POST /webhook → FastAPI app → aiogram dispatcher → Bot handlers
                                                                    ↓
                                                        ADK Agent (root_agent)
                                                        - parse_event_text (Gemini)
                                                        - get_user_credentials (SQLite)
                                                        - create_calendar_event (Google API)
                                                        - get_user_calendars (Google API)
                                                        - get_google_auth_url (Redis)

Browser → GET /oauth2callback → FastAPI → stores encrypted tokens in SQLite
```

## Success Criteria

1. Agent correctly parses event title/date/time from natural language (English and Russian) in ≥90% of eval cases
2. Agent creates event in Google Calendar with correct title, date, and time
3. Agent correctly identifies missing date/time and asks user for input
4. OAuth flow completes: user grants permission → tokens stored → calendar event created
5. Webhook is secure (secret token validated)

## Deployment

- **Target:** Cloud Run (container-based, similar to current architecture)
- **Auth:** Gemini API Key (`GOOGLE_API_KEY`) for dev; Vertex AI for production
- **Session storage:** In-memory (ADK default)
- **Prototype first:** Yes — skip CI/CD for now
